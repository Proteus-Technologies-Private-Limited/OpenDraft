Everything new since the last App Store release, for iPad and iPhone.

HEADERS AND FOOTERS GET THEIR OWN DIALOG
Format > Header & Footer, out of the bottom of Page Setup where nobody found it. Buttons insert the page number, total pages, title, date and revision colour into whichever slot you are typing in, and a preview of the first two pages shows what you will actually get.

EDIT THE HEADER WHERE IT PRINTS
Double-tap a header or footer on the page and type into it. You edit the template, so {page} stays a live page number rather than freezing as the number of the page you tapped, and every page updates at once.

PAGE NUMBERING YOU CAN SEE
A plain "Show on first page" checkbox, instead of leaving you to work it out from a page number — off is still the default, because a screenplay's first page is not numbered, and now it says so rather than looking like a bug. For a script whose opening sheet is front matter, set the number the first script page carries and everything after it follows.

FOUNTAIN FILES SURVIVE BEING SAVED
A screenplay opened from a .fountain file could come back with ** around its scene headings and the action beneath them turned into dialogue. Emphasis, scene numbers and headings that don't start with INT./EXT. are now written the way the Fountain specification asks, so a script reopens as the script you saved. Asterisks and underscores you typed yourself stay literal.

THE TITLE PAGE STAYS A TITLE PAGE
Exported scripts could open with the title, credit, draft and copyright piled at the top of page 1, the first scene heading directly underneath — a single blank line above the title was enough to cause it. A fully filled title page also lost its draft, contact and copyright off the bottom. Fixed, and an imported .fdx, .fountain, .fadein or Word title page now arrives laid out properly instead of as one near-blank page.

TWO BLANK LINES BEFORE SCENE HEADINGS
The industry standard, and Final Draft's default. OpenDraft already wrote two into every Final Draft and Fade In export while showing one on screen, so exported scripts came out longer than the app said. Existing scripts open unchanged and ask once whether to adopt it. Format > Formatting Template sets the blank lines before any element, and now reaches page breaks, PDF and Word as well as the screen.

GENERAL KEEPS YOUR INDENTATION
Text you deliberately indent in a General element stays indented, in the editor, in PDF and through Fountain and Word round-trips. Return on an indented line adds a line instead of asking you to pick an element type.

CYRILLIC AND OTHER ALPHABETS EXPORT TO PDF
A screenplay written in Cyrillic came out of PDF export as a run of unrelated Latin letters. Cyrillic, Greek, Armenian and Georgian are now written properly — same page layout, searchable and copyable. A script whose title is not in English is no longer saved as "Untitled".

EXPORTS THAT MATCH YOUR DOCUMENT
Word no longer counts the title page, so the script's opening page prints "1." and {pages} reads right, and a page 1 footer no longer vanishes when the header is set to skip it. Final Draft (.fdx) export now carries your own header, footer and page numbering instead of a fixed page number, and reads them back when you open one.

RECOVERING UNSAVED WORK
Losing power or force-quitting could still lose the last few lines: the recovery copy was written only every ten seconds. It is now written a moment after you stop typing. Beats, notes, tags, character profiles and page setup count as unsaved work too — they were not protected at all. And after a crash OpenDraft reopens the script you had open, instead of a blank page that made it look as though everything was gone.

FIXES
Choosing Take Photo to add an image no longer closes OpenDraft. Fade In (.fadein) and Open Screenplay Format (.osf) files now offer Open in OpenDraft from the Files app. Header and footer margins move the bands on screen, not only in the PDF. Long words and URLs no longer run past the right margin.
