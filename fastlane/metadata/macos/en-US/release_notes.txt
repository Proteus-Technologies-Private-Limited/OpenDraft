Everything new since 2.0.0.

PRINT PRINTS THE PAGES YOU ARE LOOKING AT
The editor draws its page turns rather than making them, and printing asked the browser to lay the script out a second time by its own rules — so the printed pages could end somewhere you had never seen, which in a screenplay is a change to the script. Print now sends the PDF, the same pages File > Export > PDF produces, so what comes off the printer is what is on screen and what anyone you send it to would read. The date, the title, the address and the page number the browser drew into the margins are gone with it.

PRINT DID NOTHING AT ALL
File > Print was a menu item that did nothing, silently and with no error to find: printing had never been permitted inside the app's own window, so the request was refused and the refusal went nowhere. It works, and if it ever cannot it now says why.

PRINTING FROM THE FILE MENU PRINTED THE FILE MENU
The print started before the menu had closed, and a menu is drawn outside everything the print styles hide, so what came out of the printer was a picture of it.

THE OLD WAY, IF YOU WANT IT
Settings > Printing turns the PDF off and hands the script to the print dialog instead, with its margin and scaling controls, which are quicker on a long script. The page breaks are then the browser's own and need not agree with the ones you see in the editor.

PASTING A LINE INTO THE MIDDLE OF ANOTHER
Paste as Fountain read an ordinary line of prose as a screenplay element and put it in as a block, which split the line the cursor was in: a scene heading pasted into came back torn in half around it. A single plain line now goes in as text at the cursor, and a line opening with "…", read as markup for the same reason, no longer is. Anything with real structure — a heading, a character cue and its dialogue, a transition, a centred line — still arrives as those elements.
