# Portable custom formats

Native scripts and backups save a complete custom format in `_templateSnapshot`, alongside `_templateId`. Built-in formats remain ID-only. Snapshot parsing validates rules, starter content, page geometry and nested settings before restoring a detached copy.

The library definition wins whenever its ID exists locally, so editing a library template continues to update existing scripts. The embedded definition is a fallback for devices without that template. Neither loading a script nor receiving a collaborative format adds anything to the recipient's library. OSF/Fade In formats use this same document-scoped path, including legacy `_templateSnapshot` data.

Formatting Template shows **This Document** only when the embedded definition differs from the library or has no library counterpart. If a local library definition exists, that is the active format. Every explicit application or edit of the document definition gives it a fresh ID, even on a device without the original template. Returning that script to its author therefore cannot replace the edit with the author’s same-ID library version. The library copy stays unchanged. When the saved copy differs from the local library, the card identifies the version currently in use and which has a later timestamp when available. **Edit Current Format** starts from the active library definition; applying the saved copy is a separate explicit choice. **Save to My Templates** creates a reusable independent copy. If storage fails, the dialog shows the error and retains the current selection so the writer can retry.

If an embedded definition cannot be parsed (including unknown fields from a future version), OpenDraft warns and uses available local formatting for display. The original snapshot, including serialized or otherwise unreadable data, stays opaque and survives native saves and backups. It is never applied as CSS or interpreted as a valid template. Choosing another format explicitly replaces it; opening a different script clears it.

Malformed edits report an error and leave the editor dialog open; they do not show Template saved. Initial library hydration and reloads of identical definitions do not mark a document unsaved. Real format changes still use the existing metadata-save path.

Collaboration shares the complete format definition and page settings with the selected collaboration server and participants. An editor collaborator can choose or edit a document format and change the shared format/layout. Viewers and suggest-only participants receive these changes but cannot publish them; their Formatting Template, Element Numbering and Page Setup controls are disabled. Local libraries remain private and unchanged; a matching library ID takes precedence locally. No new external service is contacted. Layout-only edits retain the shared definition instead of publishing a different same-ID library copy. Unsupported shared snapshots also survive layout changes. Font files are not embedded.

Regression coverage includes library precedence, subsequent library edits, clean-device fallback, OSF normalization, delayed library loading, validation failures, cross-device edits with and without a local library, opaque snapshot retention and warnings, layout-only collaboration edits, saved export resolution and Yjs metadata updates. DOCX dual-dialogue work is already on main and is outside this PR.
