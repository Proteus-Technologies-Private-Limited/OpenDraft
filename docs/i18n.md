# Internationalisation (i18n)

The interface of OpenDraft is translated. One React frontend serves every
platform (web, macOS, Windows, Linux, Android, iOS), so one translation layer
covers all of them.

**Phase 1 languages** (chosen from Play Console installs, last 28 days, 549
users): Spanish `es`, Russian `ru`, French `fr`, Brazilian Portuguese `pt`,
Persian `fa`, Arabic `ar`, Turkish `tr` — plus English `en`, the source.

**Phase 2 languages** (Indian): Hindi `hi`, Urdu `ur` (right-to-left), Marathi `mr`,
Gujarati `gu`, Telugu `te`, Tamil `ta`, Odia `or`, Punjabi `pa`, Malayalam `ml`,
Kannada `kn`, Bengali `bn`. They use Western digits and the Gregorian calendar,
need only `_one`/`_other` plurals, and are checked for their own script.
Settings → Language shows them as a grid of buttons, each under its own name.

## What is — and is not — translated

| Translated | Never translated |
|---|---|
| Menus, toolbar, dialogs, settings, toasts, errors, tooltips, `aria-label`s, placeholders | Screenplay vocabulary: `INT.` `EXT.` `CONT'D` `(MORE)` `V.O.` `O.S.`, transitions (`CUT TO:`) |
| Dates, numbers and lists the app writes (via `i18n/format.ts`) | Anything written **into a script or an export** (PDF / FDX / DOCX / Fountain / HTML) |
| Element-type *labels shown in the UI* ("Scene Heading") | Element-type *names stored in documents* (`sceneHeading`), template ids, setting values, saved presets |
| | Prompts and tool descriptions sent to an AI model (`addons/ai-assistant`) |
| | Brand and product names (OpenDraft, Final Draft, Fountain), font names, file extensions, keyboard shortcuts |
| | Release notes ("What's New") and the user manual body — English in phase 1 |

The rule behind the table: **a string the writer reads is translated; a string
a program reads is not.** If a value is compared, stored, sent to a server or
written into a file, it is data — keep it as it is and translate only what is
*displayed* for it (look up the label from the id, never the id from the label).

The **interface** language is separate from a **dialogue line's** language
(`LanguageSelector.tsx`, a per-paragraph `lang` attribute). Changing one never
changes the other.

## Layout

```
frontend/src/i18n/
  index.ts        initI18n, setLanguage, t, addPluginResources, getLanguage…
  languages.ts    the shipped languages, detection, saved preference
  resources.ts    imports every locales/en/*.json — the source of truth + key types
  format.ts       formatNumber / formatDate / formatDateTime / formatList / compareText
  useLanguage.ts  hook: current language, direction, setLanguage
frontend/src/locales/<code>/<namespace>.json
```

* English is bundled; other languages load on demand as separate chunks (they
  still ship inside the desktop/mobile apps, so everything works offline).
* The language is chosen in **Settings → Language**; the default is the
  device's language (`navigator.languages`), else English. Stored in
  `localStorage` as `opendraft:language` (`system` or a code).
* `<html lang dir>` follows the language. Arabic and Persian are `rtl`.
* Missing string in a language → the English text is shown, never a raw key.
* Keys are **type-checked**: `t('menu:file.sav')` fails `tsc`.

### Namespaces

One JSON file per namespace, per language. A namespace has one owner while the
app is being converted, so people (and agents) never edit the same file.

| Namespace | Holds |
|---|---|
| `common` | Generic words: Cancel, Save, Delete, Close, … (shared; use these before adding your own) |
| `menu` | The menu bar and its dialogs (`MenuBar.tsx`), plugin menu labels |
| `editor` | The editor surface: context menus, smart-type, spell-check menu, selection/mobile accessory bar, element picker |
| `toolbar` | Toolbar, status bar, zoom |
| `format` | Formatting panels and dialogs: fonts, page setup, headers/footers, title page, footnotes, MORE/CONT'D dialog |
| `projects` | Project list/view, open/save-as/delete, welcome, storage |
| `templates` | Script-format pickers and the template editor |
| `story` | Characters, beats, scenes, cards, relationships, timeline, locations, outline, tags, treatment, synopsis |
| `settings` | Settings page and its sections, dictionaries, grammar, voice settings, macros, shortcuts |
| `backup` | Backup and recovery |
| `collab` | Accounts, sign-in, sharing, collaboration, notes, version history, diff, external save, update/demo banners |
| `dialogs` | Cross-cutting dialogs: save errors, quota, storage fallback, toasts |
| `tools` | Statistics, reports, PDF export/import, sides, search, spell-check, suggestions, table read, goals, assets |
| `messages` | User-visible strings in non-component code: `utils/`, `services/`, `stores/`, `hooks/`, `editor/` |
| `addons` | The AI assistant and dictation add-ons (their UI — **not** model prompts) |

## Writing code

### Components

```tsx
import { useTranslation } from 'react-i18next';

const { t } = useTranslation('settings');
<button title={t('backup.chooseFolder.tooltip')}>{t('backup.chooseFolder.label')}</button>

// Using another namespace too (usually `common`): list every namespace the
// component reads, or `t('common:cancel')` fails type-checking.
const { t } = useTranslation(['settings', 'common']);
<button>{t('common:cancel')}</button>
```

### Outside React (utils, services, stores, event handlers)

```ts
import { t } from '../i18n';
showToast(t('messages:save.failed'));
```

**Never call `t()` at module scope** (constants, default arguments evaluated at
import): it runs once, in the language active at import, and never follows a
change. Build such tables lazily — a function, or inside the component.

### Interpolation and plurals

```json
"saved": "Saved {{name}}",
"scenes_one": "{{count}} scene",
"scenes_other": "{{count}} scenes"
```
```ts
t('story.scenes', { count: n })     // key is "scenes" — i18next picks _one / _other
```
English needs `_one` and `_other`. Other languages need the forms their
`Intl.PluralRules` has (Russian: one/few/many/other; Arabic: zero/one/two/few/many/other)
— the test checks it. Format numbers with `formatNumber`, never `toLocaleString()`.

### Markup inside a sentence

Use `<Trans>`; never `dangerouslySetInnerHTML`, never split a sentence into
fragments that are glued back together (word order differs per language).

```json
"hint": "Press <kbd>Enter</kbd> to <b>accept</b>."
```
```tsx
<Trans ns="editor" i18nKey="smartType.hint" components={{ kbd: <kbd />, b: <strong /> }} />
```

### Keys

* `camelCase`, nested by component/feature: `settings:backup.folder.choose`.
* **The English value is the exact English text that was in the code** — the
  English UI must not change by one character.
* One key per sentence. Do not build a sentence from several keys.
* Reuse `common:*` for the generic buttons.
* Dynamic keys (`` t(`x.${id}`) ``) don't type-check and can't be verified:
  use a lookup table whose values are literal `t()` calls, or an explicit
  `switch`.
* Translator context goes in the key name, not a comment (`file.new` /
  `file.newTitle`). A key used for two different meanings is two keys — "Open"
  the verb and "Open" the state are different words in Russian.

### Direction (Arabic, Persian)

Use CSS logical properties in anything you write (`margin-inline-start`,
`padding-inline-end`, `inset-inline-start`, `text-align: start`). The
**screenplay page is never mirrored** — margins and indents stay where the
format puts them (the document's own paragraphs carry their own `dir`); only
the app's chrome mirrors. Icons that mean a direction (back/forward arrows,
chevrons) flip; icons that don't (a magnifier, a clock) don't.

### Plugins

Plugins (OpenDraft-Pro, add-ons) bring their own words with
`addPluginResources('my-plugin-id', { en: {...}, es: {...} })` and give menu
entries `labelKey: 'my-plugin-id:export.label'` (the plain `label` stays as the
English default, so existing plugins keep working untouched).

## Adding a language

1. Add the language to `LANGUAGES` in `i18n/languages.ts` (and `LanguageCode`).
2. Copy `locales/en/*.json` to `locales/<code>/` and translate the values.
3. `npm run i18n:check`.
4. Native shells: add the language to `src-tauri/Info.plist` `CFBundleLocalizations`,
   `android/.../locales_config.xml`, and the store listings under `fastlane/metadata/`.

## Checks

```bash
cd frontend
npm run i18n:check          # tsc (keys exist) + locale integrity tests
npx vitest run src/i18n     # just the locale tests
node ../test-script/i18n_scan_literals.mjs           # hard-coded English left in the UI
node ../test-script/i18n_scan_literals.mjs --max 0   # gate: fails if any remain
```

The locale tests (`src/i18n/locales.test.ts`) fail when a language is missing a
file or key, has an extra key, drops or renames a `{{placeholder}}` or `<tag>`,
lacks a plural form its language needs, leaves a value empty, or — for Russian,
Arabic and Persian — leaves text untranslated.

Opt a deliberate literal out of the scanner with `// i18n-ignore` (same or
previous line), or wrap a block in `i18n-ignore-start` / `i18n-ignore-end`.
Say why in the comment.
