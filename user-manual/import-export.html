Import & Export

Work with Final Draft, Fountain, Fade In, Highland, WriterDuet, Celtx, PDF, and plain text formats.

Importing Scripts

OpenDraft can import screenplays from other software. Go to File > Import and select a file.

Final Draft (.fdx)

Import scripts from Final Draft, the industry-standard screenwriting software. OpenDraft preserves:

  • All screenplay elements and formatting
  • Character profiles
  • Character highlighting colors
  • Page layout settings

Fountain (.fountain)

Import scripts written in Fountain format. Fountain is an open, plain-text markup language for screenwriting. Many free tools can create Fountain files. Emphasis markup (*italic*, **bold**, _underline_), forced elements (!, ~, ., >, @), centred text (>text<) and page breaks (===) are all recognised.

Fountain’s outlining markup comes through as well, and stays off the printed page:

  • Sections (#, ##, ###…) become Section elements, nested to the depth their hashes describe, and appear in the Scene Navigator’s Structure tab. They are kept separate from New Act and End of Act, which are act markers that do print.
  • Synopses (= …) are filed on the scene heading or Section they sit under.
  • Notes ([[ … ]]) become Note elements, whether they stand alone or sit inside a line.
  • The boneyard (/* … */) is commented-out text, and is dropped.

Fade In (.fadein) and Open Screenplay Format (.osf)

Open scripts saved by Fade In directly — there is no need to export to another format first. A .fadein file is a compressed Open Screenplay Format document, and OpenDraft reads both it and plain .osf files. Imported:

  • All screenplay elements — scene headings, action, character, parenthetical, dialogue, transition and shot
  • Custom element styles, mapped to whichever built-in element they are based on
  • Bold, italic, underline, strikethrough, highlighting, fonts and sizes
  • Title page, scene numbers, dual dialogue, centring and page breaks
  • Scene synopses and paragraph notes

Highland (.highland)

Open scripts saved by Highland directly. A .highland file is a compressed bundle with the script inside it as Fountain, so it imports exactly as a .fountain file would: every element, the title page, scene numbers, dual dialogue, sections, synopses and notes. The document takes its name from the script’s title.

Highland’s own extras — the bin, sprints, gender analysis, character highlighting and images — are left behind. A Highland document written as Markdown rather than a screenplay still opens, read as Fountain; check its elements afterwards.

WriterDuet (.wdz)

Open a .wdz file saved by WriterDuet or WriterSolo. Imported:

  • Scene headings, action, character, parenthetical, dialogue, transition, shot, text, notes, acts and outline sections
  • Bold, italic and underline
  • Page breaks
  • The title page — WriterDuet keeps it as free lines, so OpenDraft sorts them into title, credit, author, draft, date, copyright and contact by what they say

WriterDuet does not publish its file format, so dual dialogue, scene numbers, comments and revision colours are not read from a .wdz. When you need those, use Export > Final Draft in WriterDuet and import the .fdx instead. An element type OpenDraft does not recognise comes in as Action, and you are told which.

Celtx (.celtx)

Open a project file from the desktop version of Celtx. Imported:

  • Film and AV scripts: scene headings, action, character, parenthetical, dialogue, transition, shot and text
  • Stage plays (acts and stage directions), radio scripts (sound, voice and music cues, production notes) and comic scripts (pages, panels, captions and balloons), each mapped to the closest OpenDraft element
  • The title page: title, byline, author, based on, copyright and contact
  • Scene numbers — production numbering such as 12A is shown and locked — and page breaks you inserted
  • Bold, italic and underline

A Celtx project can hold several scripts; the first one is imported and you are told the others were skipped. Storyboards, catalog items and breakdowns are not imported. The current Celtx web app saves to the cloud rather than to .celtx files — export Final Draft or PDF from it and import that.

ℹ️

Tip: If a file from one of these apps will not open, OpenDraft says why — for instance that it is not a valid archive, or has no script inside. Exporting Final Draft (.fdx) or Fountain from the original app always works as a fallback.

PDF (.pdf)

Import a screenplay you only have as a PDF — a script someone sent you, or one from an application you no longer use. A PDF holds no screenplay elements, only text placed on the page, so OpenDraft reads each line by where it sits: the indent of a character cue, a parenthetical or dialogue, and what the line says, the way you read a script yourself. It brings back:

  • Scene headings, action, character cues, parentheticals, dialogue, transitions and shots
  • Scene numbers printed in the margins, kept on their headings — production numbering such as 12A is shown and locked, as it would be from Final Draft
  • The title page: title, credit, author, contact and draft
  • Dual dialogue
  • Speeches carried over a page, joined back together without the (MORE) and (CONT’D)

Page numbers, headers, CONTINUED lines, revision asterisks and watermarks are left out. Bold, italics and revision colours are not read back.

ℹ️

Tip: A PDF has to contain text you can select. A scanned script is a picture of pages and cannot be imported. A PDF that needs a password to open has to be saved without one first.

Checking the import before it goes in

Reading a PDF by its indents is never perfect for a script laid out by another application — and when it goes wrong, it usually goes wrong for a whole kind of line at once, such as every character cue read as centred action. So before a PDF replaces the open script, OpenDraft shows an Import Preview: every paragraph in order, with the element it was read as, the scene it falls in, and the page and indent it came from.

  1. Select the lines that were misread. Click a line to select it, Shift-click to select a range, and ⌘/Ctrl-click or tick its box to add a line. ↑/↓ move through the list and ⌘/Ctrl+A selects every line shown.
  2. Widen the selection in one step. Same type selects every line of the element(s) you have selected; Same indent selects every line that sat at the same indent, in the same case — usually exactly the lines that were misread together.
  3. Set their element with the Set type menu, or press 1–8 (in the order the menu lists them). Changed lines are highlighted, and Undo or Revert all take changes back.
  4. Use Show to list only one element, or only the lines you have changed.
  5. Press Import to bring the script in with your corrections, or Cancel to leave the open script exactly as it was.

On a phone or tablet, tick the boxes to select several lines, and tap Range… and then a line to select everything from the last line you picked to that one. Dual dialogue is shown but cannot be changed here — fix it in the script after importing. Lines can only be given a different element in the preview; to split or join paragraphs, edit them after importing.

The preview appears wherever a PDF is imported: File > Import, the welcome screen, dragging a PDF onto the editor, opening one from your computer or phone, and Import Script in a project.

Plain Text (.txt)

Import plain text files. OpenDraft will attempt to detect screenplay element types based on formatting conventions (indentation, capitalization, etc.).

ℹ️

Tip: For best results when importing plain text, make sure your text follows standard screenplay formatting conventions (scene headings in all caps starting with INT./EXT., character names in all caps and centered, etc.).

Paste as Fountain

To bring in part of a script rather than a whole file, copy the Fountain text and use Edit > Paste as Fountain (or Shift+Cmd/Ctrl+V, also on the right-click menu). The pasted text is run through the Fountain parser and inserted at the cursor as real screenplay elements, instead of landing as one block of whatever element you were already in.

A single line of ordinary text is the exception. Fountain calls anything it does not recognise Action, so pasting Across the yard in the middle of a scene heading would otherwise break the heading in two and drop an Action line between the halves. Text like that is inserted at the cursor instead, keeping the element you are in — exactly as an ordinary paste would. Anything Fountain does recognise, including a line you have marked as Action yourself with a leading !, still arrives as its own element.

ℹ️

Tip: This is the quickest way to move a scene from a forum post, an email, a notes app or another screenwriting tool into your script.

Open A File Where It Lives

Importing brings a copy of a screenplay into your library. Opening in place does something different: it edits the file itself, wherever it is, and Save writes back to it.

  1. Go to File > Open File from Disk on the desktop, or File > Open from Files on iPad, iPhone and Android.
  2. Pick a .odraft, .fdx, .fountain, .fadein, .osf or .txt file.
  3. Write. ⌘S saves straight back to the original file — including files in iCloud Drive, Google Drive or Dropbox.

On the desktop, a screenplay you open by double-clicking it in Finder or Explorer stays attached to itself the same way, so Save updates that file rather than filing a copy in your library.

ℹ️

Opening another application’s format? OpenDraft says what saving back to it can and cannot carry before you start. Notes, tags, beats and character profiles have nowhere to live in a .fdx or .fountain file, so use File > Save to Library As to keep a lossless .odraft copy alongside it.

Exporting Scripts

Everything below is under File > Export. On phones and tablets, exporting opens the system share sheet so you can put the file in Files, Drive, Dropbox, or send it straight to someone.

Final Draft (.fdx)

Go to File > Export > Final Draft (.fdx). This creates a .fdx file that can be opened in Final Draft or any software that supports the format. Preserved data includes:

  • All screenplay elements and formatting
  • Character names and descriptions (rich text descriptions are converted to plain text, since FDX only supports plain text in character bios)
  • Character highlighting colors
  • Tag categories and entities
ℹ️

Note on character profiles: OpenDraft's extended character fields — Role, Backstory, and character images — are preserved in OpenDraft's native save format but are not included in FDX exports. The FDX format (used by Final Draft) only supports character name, plain text description, and highlight color.

Fountain (.fountain)

Go to File > Export > Fountain (.fountain). This creates a plain-text Fountain file that can be opened in any Fountain-compatible editor or version control system.

⚠️

Fountain cannot carry every element. It has no General element, so OpenDraft writes General as forced Action (!). Import that file again and the text comes back as Action, not General. The same applies to Shot, New Act, End of Act, Show/Episode and Cast List. Use .fdx, .docx or .odraft if you need those preserved — see Format Compatibility for the full mapping.

Fade In (.fadein)

Go to File > Export > Fade In (.fadein). This writes a Fade In document — an Open Screenplay Format archive that Fade In 3 and 4 both open. It carries a great deal more than Fountain does:

  • All screenplay elements, and custom element styles
  • Bold, italic, underline and strikethrough, colour and highlighting
  • Per-selection font and size, and hard line breaks
  • Forced page breaks, scene numbers, synopses and dual dialogue
  • The title page

Notes, tags, beats and character profiles have no home in the format, so they are left out rather than written as something Fade In would misread. Keep a .odraft copy if you need them.

Microsoft Word (.docx)

Dual dialogue exports both speeches in a borderless two-column table, keeping cues, parentheticals, inline styles and line breaks. Word controls pagination for long exchanges. Importing the file restores the two dialogue columns.

Go to File > Export > Microsoft Word (.docx) for a formatted document to share with people who do not use screenwriting software.

The title page is included unless you have turned it off in Format > Title Page — see Leaving the Title Page Out.

OpenDraft (.odraft)

Go to File > Export > OpenDraft (.odraft). This is the lossless one: the script plus its notes, tags, beats, character profiles and images, in a single file. Use it to move a screenplay between machines, or to keep a complete copy of your own. It is the same format backups are written in.

PDF

Go to File > Export > PDF. The PDF is formatted to industry-standard screenplay specifications.

Before exporting to PDF, you may want to:

  • Turn off note highlights (View > Note Highlights)
  • Turn off tag highlights (View > Tag Highlights)
  • Check your Page Setup settings
  • Decide whether to include the title page — the checkbox at the bottom of Format > Title Page. See Leaving the Title Page Out.

Scripts in Other Languages

A script doesn’t have to be in English to export. OpenDraft carries its own fonts for PDF export, so the PDF looks the same on every computer and phone you send it to, whether or not they have those fonts installed:

  • Indian scripts — Tamil, Hindi, Marathi, Nepali, Bengali, Gujarati, Punjabi, Odia, Telugu, Kannada, Malayalam and Sinhala. Letters are formed exactly as they are on screen: vowel signs sit on the right letter, Tamil’s கு, டு and ரு are drawn as the single letters they are, and joined letters such as क्ष and the reph in कर्म come out joined.
  • Cyrillic, Greek, Armenian and Georgian — drawn on the same fixed-width grid as English, so the page layout is unchanged.
  • Hebrew and Arabic — each line reads right to left, and Arabic letters are joined. The page itself is not mirrored: margins and indents stay where a standard screenplay puts them.
  • Thai.
  • Chinese, Japanese and Korean — these fonts are too large to include, so they are downloaded the first time you export a script that uses them, and kept for next time. That first export needs an internet connection.

Text you copy out of the PDF, or search for in a PDF reader, matches what you typed.

ℹ️

Tip: If a script uses a writing system OpenDraft can’t put in a PDF yet — Lao, Tibetan, Myanmar, Khmer or Ethiopic, for example — the export still finishes and tells you which one, rather than leaving gaps without saying so.

PDF with a Watermark or Password

Go to File > Export > PDF with Watermark or Password… before sending a script out.

  • Watermark — text across the middle of every page, or a small line at the foot, at the strength you choose. CONFIDENTIAL by default.
  • One copy per recipient — type one name per line and each copy is watermarked with its reader’s name, so a leaked copy says whose it was. Put {recipient} in the watermark text to place the name yourself (“Copy for {recipient}”). The copies are saved together in a .zip.
  • Password to open, and whether a reader may print or copy text.
⚠️

PDF passwords and restrictions use the PDF standard’s basic encryption. They stop casual copying, but determined software can remove them. The watermark is what identifies a copy.

Sides & Selected Pages

Go to File > Export > Sides & Selected Pages… to export only some of the script’s pages. Every page keeps the page number and scene numbers it has in the full script, so the pages match everyone else’s copy.

  • Sides — tick the scenes an actor needs, or choose a character and press Add to tick every scene they speak in. With Cross out the rest of each page on, the parts of each page that belong to other scenes are struck through, as sides are marked by hand.
  • Pages with a character — every page where that character speaks.
  • Pages at a location — every page of the scenes set there.
  • Pages with a tag — every page holding an element with that production tag, for the department that looks after it.

The title page is never included.

Tick Two pages per sheet (landscape) to put the pages side by side, two to a landscape sheet of the script’s own paper (Letter or A4), scaled down to fit — the way sides are usually handed out on set. Each page keeps its own page number, scene numbers and cross-outs. With an odd number of pages, the last sheet has one page on it.

The dialog has a Print… button beside Export PDF…, so the same pages can go straight to the printer — see Printing selected pages.

Printing

Go to File > Print or press ⌘P to print your screenplay directly.

What gets printed is the PDF — the same pages File > Export > PDF produces — so the printed script matches both what is on screen and what you would have sent anyone. On the desktop the PDF opens in whatever your computer uses for PDFs and you print from there; in a browser it goes straight to the print dialog.

On phones and tablets there is nothing to choose: neither has a print dialog of its own, so Print hands the script to the system. On iPhone and iPad it appears in the share sheet, where Print sits alongside Save to Files and AirDrop; on Android it opens the standard Android print dialog, which also offers Save as PDF.

Printing selected pages

Go to File > Print Selected Pages… to print sides, or only the pages with a chosen character, location or production tag. It opens the Sides & Selected Pages dialog with Print… as its main button; choose what to print, tick Two pages per sheet if you want them two-up, and press Print….

The pages go to the printer the same way File > Print sends the script: opened in your PDF viewer on the desktop, the print dialog in a browser, the share sheet on iPhone and iPad, and the Android print dialog on Android. They are always printed from the PDF, even if Print the PDF is turned off below — only the PDF can leave pages out and keep each one’s page number.

Printing the page instead

On the desktop and in a browser, Settings > Printing has a switch: Print the PDF, so the pages match the ones on screen. It is on to begin with.

Turn it off and Print uses the browser's own dialog on the page itself. That is quicker on a long script, and it is what the dialog's margin and scaling controls apply to — but the browser then decides where the pages end, and it does not always agree with the editor, so a page can break somewhere you have not seen. For a script going to anyone else, leave the switch on.

ℹ️

The switch is not on iPad, iPhone or Android, because there is no second way to print on those devices for it to choose between.
