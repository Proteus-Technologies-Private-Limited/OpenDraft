Welcome to OpenDraft

The free, open-source screenwriting application. This manual will help you get started and master every feature.

💡

New to screenwriting software? Start with the Getting Started guide for a quick walkthrough of writing your first screenplay.

Quick Start

  1. Install OpenDraft — Download the desktop app for macOS, Windows, or Linux, or run it in your browser.
  2. Create a project — Click New Project on the Projects screen, give it a name, and open it.
  3. Start writing — Click New Script inside your project, and begin writing your screenplay. OpenDraft handles formatting automatically.
  4. Save your work — Press ⌘S to save, or use File > Versions > Check In to create a version checkpoint you can return to later.

What's New

v0.25.0

  • A Font Library Worth The Name — Around 185 fonts, grouped by what they are: screenplay, typewriter, serif, sans-serif, monospace, display faces for title pages, handwriting, and the Noto families covering most writing systems. The picker searches, and every name is drawn in its own face. Courier Prime 12pt is still what a new script is. See Fonts.
  • Install Your Own Fonts — Format → Fonts… takes TrueType and OpenType files. The family name is read out of the font itself, so weights group together. Because OpenDraft holds the file, a font you install is embedded in exported PDFs. See Adding Your Own Fonts.
  • The Fonts Already On Your Device — Faces from your operating system are checked before they are offered: one this platform hasn’t got is greyed out and marked not installed, instead of silently rendering as Courier. On iPad and Android, where no app can list installed fonts, you can add one by name.
  • A Font Choice Travels With The Script — Open a script on a machine without the font and OpenDraft substitutes the closest match of the same kind — a typewriter face for a typewriter face, a serif for a serif — rather than dropping everything to Courier. The original name is kept, so the font returns the moment you open it somewhere it exists. See Fonts Across Devices.
  • The Title Page Is Part Of The Template — Title, Credit & Author, Draft & Date, Contact, Copyright and Notes are formatting elements like any other, so you can set the title in a display face at 24pt and leave the contact block in Courier. Anything you change by hand outranks the template and stays put. See Formatting Templates.
  • Comfortable On A Tablet — Touch devices start in the comfortable toolbar, and the menus, font list and dialogs have finger-sized targets rather than mouse-sized ones. The font picker no longer closed itself the instant the on-screen keyboard appeared, which on iPad made tapping it look like it did nothing at all.
  • Cut, Copy And Paste From The Menus — All three ran on the DOM selection, and tapping a menu item takes focus out of the editor — which on iOS collapses the selection with it, so Cut and Copy silently did nothing and Paste had never worked from a menu at all.
  • Pasted Text Keeps Its Font — A paste used to have every font stripped out of it. It now keeps the face it came with, while taking the element type of wherever it lands.
  • Highlights Come Across — Google Docs, Word Online, Notes and the browsers all write a highlight as a coloured background rather than a <mark>, so a highlighted sentence pasted in as plain text. It arrives highlighted now.
  • Images Live Outside The Document — An image added to a script with no project behind it was embedded inside the document, where a single phone photo weighed about as much as five hundred pages of screenplay — enough to push the file past the crash-recovery limit and leave it with no crash protection at all.
  • Android: Back At The First Screen — Pressing Back on the opening screen now backgrounds the app, the way every Android app does, instead of tearing down the view and reopening to a blank white page.

v0.24.1

  • Header & Footer Has Its Own Dialog — Format → Header & Footer, out of the bottom of Page Setup where nobody found it. Buttons insert the page number, total pages, title, date and revision colour into whichever slot you are typing in, and a preview of the first two pages shows what you will actually get. See Headers & Footers.
  • Edit The Header Where It Prints — Double-click a header or footer on the page and type into it. You edit the template, so {page}. stays a live page number rather than freezing as the number of the page you happened to click. Enter keeps the change, Escape drops it, and it updates every page and the settings dialog at once. See Editing On The Page.
  • Show The Page Number On Page 1 — A plain Show on first page checkbox, instead of a Start on page number box you had to reason about. Off is still the default, because a screenplay's first page is not numbered — and now it says so rather than looking like a bug. See The First Page.
  • Start Numbering At Any Page — For a script whose opening sheet is a synopsis or other front matter, set the number the first script page carries and everything after it follows. {page} and {pages} both shift with it, on screen and in every export. See Starting Page Number.
  • Word Exports Number Pages Correctly — With a title page, Word counted it, so the opening page of the script printed “2.” and carried a header the layout said to hide; {pages} read one page too many. A footer set to appear on page 1 also vanished whenever the header was set to skip it, because one switch decided both. Each band is now decided on its own.
  • Final Draft Exports Carry Your Header — .fdx export wrote a fixed right-aligned page number whatever your document said, and never wrote a footer at all. Your own header, footer, first-page rule and starting page number now go out with the file, and come back when you open one. See Import & Export.
  • Header And Footer Sit Where You Put Them — The header and footer margins now move the bands on screen too, instead of only in the PDF.

v0.24.0

  • Fountain Files Survive Being Saved — A screenplay opened from a .fountain file could come back with ** around its scene headings, and the action beneath them turned into dialogue. Emphasis, scene numbers and headings that don't start with INT./EXT. are now written the way the Fountain specification asks, so a script reopens as the script you saved. Asterisks and underscores you typed yourself stay literal instead of turning into italics. See Import & Export.
  • The Title Page Stays A Title Page — Exported scripts could open with the title, credit, draft and copyright piled at the top of page 1 and the first scene heading directly underneath. A single blank line above the title was enough to cause it, and a fully filled title page quietly lost its draft, contact and copyright off the bottom of the page. A title page with no title at all was dropped from PDF and Word entirely. All of it is fixed, the title page no longer takes a page number of its own, and an imported .fdx, .fountain, .fadein or Word title page now arrives laid out properly instead of as a single near-blank page. See Title Page.
  • Recovering Unsaved Work On iPad — Losing power or force-quitting could still lose the last few lines: the recovery copy was only written every ten seconds, and a sudden stop inside that window wrote nothing at all. It is now written a moment after you stop typing. Work that never touches the script itself counts too — beats, notes, tags, character profiles and page setup were not being protected at all. And after a crash OpenDraft reopens the script you had open, instead of starting on a blank page that made it look as though everything was gone. See Backups & Recovery.
  • Two Blank Lines Before Scene Headings — The industry standard, and Final Draft's default. OpenDraft already wrote two into every Final Draft and Fade In export while showing one on screen, so exported scripts came out longer than the app said. Scripts written under the old spacing open unchanged and ask once whether to adopt it.
  • Space Before Is A Real Setting — Format → Formatting Template sets the blank lines before any element, counted in lines. It now reaches page breaks, PDF and Word as well as the screen — before, changing it moved the gap on screen only, and the page count stayed where it was.
  • General Keeps Your Indentation — Text you deliberately indent in a General element stays indented, in the editor, in PDF and through Fountain and Word round-trips. Pressing Enter on an indented line adds a line instead of asking you to pick an element type and quietly changing it.
  • Clearer Element And Menu Names — General is now General (Unformatted text), and the element pickers explain what the less obvious elements are for. The File menu now says Script rather than Screenplay, because five of the six formats you can choose are not screenplays: New Script, Open Script…, Close Script. And Save names where it is going — a script you opened from a file says Save to File, so it is clear ⌘S overwrites that file rather than filing a copy.

v0.23.2

  • Cyrillic Scripts Export To PDF — A screenplay written in Cyrillic came out of PDF export as a run of unrelated Latin letters. Cyrillic, Greek, Armenian and Georgian are now written into the PDF properly — on the same page layout as before, and searchable and copyable out of the file. Title pages, headers and footers too. See PDF.
  • Exports Keep The Title In The Filename — A script whose title was not written in English was saved as Untitled. The title now survives into the filename, in any alphabet, for PDF, Word, Final Draft, Fountain and Fade In exports.

v0.23.1

  • Taking A Photo No Longer Closes The App — On iPhone and iPad, choosing Take Photo when adding an image to a script, title page, character profile or beat board shut OpenDraft down on the spot. It now asks for the camera and returns your photo.
  • Fade In Files Open From Files Again — .fadein and .osf files offer Open in OpenDraft on iPhone and iPad, as they were always meant to. App Store builds had been shipping without the declarations that make the two formats visible to the Files app. See Open A File Where It Lives.

v0.23.0

  • Automatic Backups On iPad, iPhone And Android — Timed backups are no longer desktop-only. Choose a folder in Files, iCloud Drive, Google Drive or Dropbox and OpenDraft writes the same timestamped copies it writes on the desktop — same filenames, same per-project folders, so a backup made on your Mac restores on your iPad. On phones and tablets a copy is also written whenever you leave the app, before the system can suspend it. See Backups & Recovery.
  • More Than One Window — File > New Window opens a second window on iPad, on Android 12L and later, and on the desktop. Opening a screenplay that is already open in another window offers to switch to it rather than open a second copy that would save over the first. See Working In More Than One Window.
  • Open And Save Files Where They Live — File > Open File from Disk (Open from Files on mobile) edits a .fdx, .fountain, .fadein, .osf, .odraft or .txt in place: Save writes back to the original file instead of filing a copy in the library. See Open A File Where It Lives.
  • Export To Fade In — File > Export > Fade In (.fadein) writes a real Fade In file, carrying elements, emphasis, colour and highlighting, fonts, forced page breaks, scene numbers, synopses, dual dialogue and the title page. See Fade In.
  • Recovering Unsaved Work Is Safer — The recovery prompt appears only when the document really was edited, asks once per launch before anything else, and keeps a separate snapshot per window so two windows cannot overwrite each other’s protection.
  • Close, And A Way Back — File > Close on every platform, a back button on the projects screen at last, and every close control is now big enough to hit with a thumb.
  • Fixes — Saving a file opened in place no longer leaves it asking to be recovered on the next launch. Starting a new screenplay while a file is open no longer leaves Save aimed at that file.

v0.22.0

  • Start Any Element On A New Page — Put the cursor in an element and choose Format > Start On New Page to force a page break before it. A tick shows while it’s on. The flag is saved with the script, exports to Final Draft and Fountain (as ===), and is read back from .fdx, .osf and .fountain files you import. See Page Breaks.
  • Acts On Their Own Page — Templates can require an element to open a fresh page: tick Starts on a new page against any element in the template editor. The 1-Hour TV Drama, Multi-Cam Sitcom and Stage Play formats break before every New Act out of the box, on screen and in PDF/Word exports. See Every act, automatically.
  • Fonts In Exports — The typeface you choose now survives export: PDF, Word and Final Draft carry the document font and any per-selection font, and Final Draft files bring their own typeface in on import.
  • More Fonts In The Picker — Times New Roman, Georgia, Helvetica, Verdana, Tahoma and Trebuchet MS are now listed under a new System group, instead of appearing only after you imported a document that used one.
  • Font Picker Styles The Selection — Choosing a font or size styles just the selected text rather than redefining the document’s own font; picking the document font clears the override again.
  • Page Break Fixes — A scene heading no longer swallows the act that follows it, which had put every act on one page until you typed inside the scene. Changing formatting template now repaginates straight away instead of waiting for your next keystroke, and pressing Enter into a new page now scrolls there.

v0.21.0

  • Open Fade In Scripts — Import .fadein files straight from Fade In, along with Open Screenplay Format (.osf) files. Use File > Import, drag one onto the editor, or just double-click the file. Elements, custom element styles, bold/italic/underline, highlighting, fonts, the title page, scene numbers, synopses, dual dialogue, centred text and page breaks all come across. See Import & Export.
  • Paste as Fountain — Copy Fountain text from anywhere and use Edit > Paste as Fountain (⇧⌘V, or Ctrl+Shift+V on Windows and Linux) to drop it in as real scene headings, character cues, dialogue and transitions instead of one undifferentiated block. Also on the right-click menu.
  • Better Fountain Import — Emphasis (*italic*, **bold**, _underline_) now arrives as formatting rather than literal asterisks, and forced action (!), lyrics (~), centred text (>text<) and page breaks (===) are recognised.

v0.20.0

Back up on demand with File > Backups > Back Up Now, and restore any snapshot with Recover Backup. Backups include notes, tags, beats, characters and images, and live outside the app's database. (Desktop only.)
  • Hard Line Breaks — Shift+Enter starts a new line inside an element without creating a new one. Breaks are preserved in PDF, Word, Final Draft and Fountain exports.
  • More Reliable Saving — Manual saves no longer drop per-script spelling and grammar settings, and exported .odraft files carry all of a script's notes, tags, beats and character profiles.
  • Your Script Survives a Trip to Settings — Opening Settings or the project list and coming back no longer leaves the editor blank.

v0.19.0

  • Mobile-Friendly Title Page — The Title Page editor adapts to small screens: the form and live preview stack vertically and the dialog fits the viewport, so there's no horizontal scrolling on phones.

v0.18.0

  • Redesigned Title Page — Manage title-page images, choose a larger title font size, and preview the page live. Editor, preview and PDF/DOCX exports all match.
  • Mores & Continueds — A Format dialog to control automatic character (CONT'D) and the (MORE)/(CONT'D) at dialogue page breaks, with customizable marker text.
  • Smarter (CONT'D) — (CONT'D) no longer carries across a new scene, and deleting it at a specific cue is remembered. Manually typed (CONT'D) is never removed.
  • Larger Font Sizes — The font-size menus now go up to 96pt.
  • Data-Loss Protection — A safeguard prevents a blank or just-loaded editor from overwriting a saved script with an empty document.
